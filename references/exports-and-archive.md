# 复制、导出与存档

## 单条与全部复制

- 单条复制在旁批行末灯泡旁；全部复制在底部工具岛旁。按钮可显示简短 ID，但复制必须包含完整 UUID。
- 复制内容按稳定顺序包括：篇目／原页码、ID、段落和字符范围、原句、中文对应、修改建议、必要的不确定说明。
- 明确替换写 `原文\n↓\n改后`；一处可包含多个改点，不强拆成数条。尚未确定的旁批明确“尚未确定”，不把候选当作用户决定。
- 以用户当前编辑的 note 为准，不优先输出旧的 suggestion.after。单条和全图复制调用同一内容整理逻辑。
- navigator.clipboard 成功才能说已复制；失败时展示并选中纯文本，供 Cmd+C。lastCopied 保存实际内容、ID、篇目、时间与类型。
- 用户原本希望“一点击就作为聊天附件”；缺少宿主桥接时采用复制键，不假装自动上传附件或已经发送。

## 高清 PNG

底部导出图片按钮只导出当前整张裁切后的稿纸，不发送聊天、不提交全部修改。

必须包含：英文与中文原件、原有荧光、旁批、边框、ID、圈线和引线。排除：工具岛、调色盘、垃圾桶、最近删除列表、预览幽灵。

- 显示用原图保持原字节；另从同源 PDF 按原页边界渲染 300dpi 的 `p<page>-en/zh-export.png`。
- 输出比例取高清图 naturalWidth/显示宽度、naturalHeight/显示高度的最大值，至少保留全部高清像素。不能随当前 zoom 或任意 4000px 上限降采样。
- 不能放大低清截图并称为高清。保留 PNG 无损。
- 超过 Canvas 安全尺寸（当前实现约 32767px 或 200M 像素）时报错，不偷偷降低清晰度。
- `POST /api/export-image` 保存 exports/PNG 与 metadata JSON，并返回真实文件和下载 URL。导出的中间原件文字要实际检查清晰度。

## 可继续编辑的单文件 HTML

工具包“导出可编辑文件”调用 `/api/export-editable {docId}`。

`scripts/portable_export.py` 与 `assets/app/portable-bootstrap.js` 会内嵌：当前篇目双语原图、高清专用图、透明文字坐标、全部批注、颜色、位置、尺寸、必要 CSS/JS。它必须不依赖 localhost 服务或旁边文件。

- 原件仍是图片；可编辑的是旁批、笔迹、圈线和布局，不能说正文已变成 Word 文本。
- 收件人在浏览器里的变动保存在该 HTML 独立 localStorage。要发回新版本，必须再点一次“导出可编辑文件”；浏览器自动保存不等于写回原 HTML 文件。
- 再次导出要内嵌最新状态并生成新的 exportId，防止别人打开两份文件却共用同一份浏览器草稿。
- standalone 模式不宣称本机 OCR 服务可用；不自动上传或分享给第三方。
- 验证嵌入资源完整、刷新后编辑保留、再次导出含新文、源 draft 未被改动。若某种本地 URL 被安全工具拒绝，不换通道绕过；用允许的隔离静态站点验证逻辑，准确说明未测试的打开方式。

## 存档当前面

用户说“这一面存档”是冻结当前画布，不是归档聊天。先读 draft.pageIndex 确认是哪篇。

```bash
python scripts/archive_workspace.py --root '/absolute/workspace' --doc-id DOC01
```

不写死默认篇目。脚本创建新时间戳目录和 ZIP，包含可编辑 HTML、当前篇目原图与高清图、该篇状态、源 metadata、SHA256 manifest 和简短说明。每次新建，不覆盖旧档。原来的实时 draft 不动。

导出、存档和应用母稿是三个独立动作；授权存档不等于授权应用或分享。
